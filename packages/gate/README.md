# @mg/gate

道具の呼び出しなどを、人に聞かずに実行してよいか判定する口のパッケージです。

## 役割

- 判定の口の型を決めます。
  受け取るのは、種類と説明文と元の値です。
  返すのは、可否と理由です。
- 方針の文章と接続先とモデルから、LLM で判定する実装を作れます。
- 判定そのものが失敗したときのための、専用の例外を持ちます。

### 型と実装の分け方

core の接続先と同じ考え方です。
判定の口は、入力と出力を型で固定します。

中身は差し替えられます。
最初の実装は、方針の文章を LLM に読ませて判定するものです。
規則だけで判定する実装も、同じ型で作れます。

型を固定することで、判定の口を付ける側は中身を知らずに済みます。
中身を差し替えても、付ける側の書き直しは要りません。

### LLM の実装

`createLlmGate` は、方針の文章と接続先とモデルを受け取ります。
受け取ったものから、判定の口を作ります。

判定するたびに、接続先へ 1 回だけ問い合わせます。
送るのはシステムの指示と方針の文章、それに判定したい内容です。
判定したい内容は、渡された説明文そのままです。

答えの形は、判定専用の道具の呼び出しを強制して固定します。
道具から返った値を検証し、可否と理由に変えます。

## やらないこと

- 判定を記録には残しません。
- 道具の呼び出しを文章に変える処理は持ちません。
  道具の実行に付ける口の側が持ちます。
- ハーネスのループや runner への組み込みは持ちません。
- 記録を見る画面には手を入れません。
- 規則だけで判定する実装は、まだ持ちません。

## 使い方

`createLlmGate` に渡すものを表にまとめます。

| 名前       | 内容                       |
| ---------- | -------------------------- |
| `provider` | 使う接続先                 |
| `model`    | 使うモデルの名前           |
| `policy`   | 判定の根拠にする方針の文章 |

```ts
import { createLlmGate } from "@mg/gate";

const gate = createLlmGate({
  provider,
  model: "openai/gpt-4o-mini",
  policy: "読み取り専用のコマンドだけ、聞かずに実行してよい。",
});

const verdict = await gate.judge({
  kind: "tool-call",
  description: "Runs `bash` with command: rm -rf /",
});

// verdict は { allowed: boolean, reason: string }
```

判定そのものが失敗すると、`GateError` を投げます。
元の例外は `cause` に残ります。

中断の合図だけは、包まずにそのまま通します。
`context.signal` に中断済みの合図を渡すと、接続先を呼ばずに投げます。
