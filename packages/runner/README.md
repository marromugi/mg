# @mg/runner

設定ファイルから接続先とハーネスを組み立てて、走らせるパッケージです。

## 役割

runner の役割は 4 つです。

- 設定ファイルの型 `RunConfig` と、それを作る `defineRun` を持ちます。
- 設定を 1 件走らせる `run` を持ちます。
- 設定を複数件まとめて走らせる `runMany` を持ちます。
- 設定ファイルをパスから読み込む `loadRun` を持ちます。

### 走る流れ

`run` が結果を返すまでの流れです。

- 設定の `trace` から、記録の組み立てを作ります。
- 設定の `harness.kind` に合わせて、ハーネスを組み立てます。
- 設定の `gate` を、そのままハーネスに渡します。
- ハーネスに会話を渡し、出来事を集めて結果にします。
- 根の期間を閉じ、記録の書き出しを待ってから返します。

### 判定

設定に判定の口 `gate` を書くと、道具を実行する前にその判定を
挟むハーネスが組み立ちます。runner は判定の実装を知りません。
@mg/gate で作った判定の口を、そのまま設定に渡します。

書き方は `agent-guide.md` にまとめています。

### 記録

`run` は、走った 1 回分を `mg.run` の期間として記録します。
その `mg.run.name` には、設定の `name` が入ります。

`runMany` から走らせたときは、`mg.run.case` に件の ID も入ります。
記録の書き出しに失敗すると、走行が成功していても例外になります。

## やらないこと

次のことは runner の外に任せます。

- ハーネスの実体は持ちません。`harness.kind` に応じて @mg/harness-loop などから組み立てます。
- 接続先や道具の実体は持ちません。@mg/core や @mg/tools から渡します。
- 判定の実装は持ちません。@mg/gate から作った判定の口を渡します。
- 記録の実体は持ちません。@mg/trace の組み立てを使います。
- コマンドラインからの実行は持ちません。

## 使い方

設定ファイルの書き方と、選べる項目の一覧は `agent-guide.md` にまとめています。
ここでは、走らせ方だけを示します。

```ts
import { run } from "@mg/runner";
import config from "./loop-bash.config.ts";

const { sessionId } = await run(config, [
  { role: "user", content: "..." },
]);
```

複数件をまとめて走らせるときは `runMany` を使います。
設定ファイルをパスから読み込みたいときは `loadRun` を使います。

項目の詳しい意味や見本は `agent-guide.md` を見てください。
